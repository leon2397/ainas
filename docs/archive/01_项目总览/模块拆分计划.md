# AI-NAS V7.0 模块拆分计划

> 制定日期：2026-04-17
> 策略：方案 A 轻量拆分（不改变运行方式，只重组代码结构）
> 原则：**不破坏现有功能，渐进式迁移**

---

## 一、拆分目标结构

```
AI-NAS-V7.0.0/
├── backend/
│   ├── modules/                    ← 新增：各独立模块
│   │   ├── mod-auth/               # 认证与权限
│   │   ├── mod-database/           # 数据库层
│   │   ├── mod-media/              # 媒体管理
│   │   ├── mod-ai/                 # AI 引擎
│   │   ├── mod-storage/            # 存储驱动
│   │   ├── mod-monitor/            # 监控告警
│   │   ├── mod-enterprise/         # 企业功能
│   │   └── mod-plugins/            # 插件系统
│   ├── core/                       ← 保留：基础设施（不拆）
│   ├── routes/                     ← 保留：API 路由（薄层）
│   ├── main.py                     ← 保留：启动入口
│   └── tests/                      ← 保留：测试
```

每个模块内部结构统一：
```
mod-xxx/
├── __init__.py         # 对外暴露接口
├── service.py          # 核心业务逻辑（从 services/ 迁入）
├── models.py           # 数据模型（从 database/db.py 拆出）
├── schemas.py          # Pydantic 请求/响应模型
├── exceptions.py       # 模块专属异常
├── tests/              # 模块独立测试
│   ├── __init__.py
│   └── test_xxx.py
└── README.md           # 模块说明
```

## 三、执行顺序

```
Week 1：P1 模块（最小可用集）
  Day 1-2：mod-database（基础，其他依赖它）
  Day 3-4：mod-auth（独立性强，先拆）
  Day 5-7：mod-ai（核心价值，重点打磨）

Week 2：P1 模块续 + P2 模块

Week 3：P3 模块 + 整合测试
  Day 1-3：mod-enterprise
  Day 4-5：mod-plugins
  Day 6-7：整合测试，验证 main.py 正常启动
```

## 四、迁移规则（重要）

### 规则 1：先复制，后删除
```
不要直接移动文件！
步骤：
1. 在 modules/mod-xxx/ 创建新文件
2. 把代码复制过去，调整 import 路径
3. 在原文件加 deprecation 注释
4. 确认测试通过后，再删除原文件
```

### 规则 2：import 路径兼容
```python
# 原来
from services.scanner import MediaScanner

# 迁移后（routes/ 里改成这样）
from modules.mod_media import MediaScanner

# 过渡期：原文件保留转发
# services/scanner.py（过渡期保留）
from modules.mod_media.scanner import MediaScanner  # 转发
```

### 规则 3：每个模块必须有独立测试
- 迁移完一个模块，立即补测试
- 测试通过才算迁移完成

### 规则 4：main.py 不动
- main.py 只改 import 路径
- 启动方式不变
- 对外 API 不变

## 六、风险控制

| 风险 | 应对 |
|------|------|
| 循环依赖 | 严格分层：core → mod-database → 其他模块 |
| import 路径混乱 | 过渡期保留原文件转发，不急着删 |
| 测试失败 | 每个模块独立测试，发现问题立即停止 |
| 时间超预期 | P3 模块可以不拆，保持原样也能运行 |
