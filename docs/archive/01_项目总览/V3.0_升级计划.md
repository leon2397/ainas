### Phase 2：API 统一（Week 3-4）

**目标**：统一 ARM 和 Windows 的 API 接口

#### 2.1 统一响应格式

```python
# 统一响应格式
{
    "code": 0,        # 0=成功，其他=错误码
    "data": {...},     # 响应数据
    "msg": "success",  # 消息
    "timestamp": "..."  # 时间戳
}
```

- [ ] 创建统一响应中间件
- [ ] 更新所有路由返回格式
- [ ] 更新 Swagger 文档
- [ ] 前端适配新格式

#### 2.2 统一 API 路由

| 原 Windows 路由 | 统一路由 | ARM 兼容 |
|-----------------|----------|----------|
| `/api/media/upload` | `/media/upload` | ✅ |
| `/api/albums/create` | `/albums/create` | ✅ |
| `/health` | `/health` | ✅ 已有 |

- [ ] 创建统一路由适配层
- [ ] ARM 服务更新路由前缀
- [ ] Windows 服务移除 `/api` 前缀
- [ ] 验证两个版本 API 兼容

#### 2.3 统一配置格式

- [ ] ARM 使用与 Windows 相同的 YAML 配置
- [ ] 统一环境变量覆盖机制
- [ ] 统一默认值处理

**验收标准**：ARM 和 Windows 服务 API 格式完全一致

- [ ] 批量处理优化

| 相册列表 | < 200ms |
| 媒体搜索 | < 500ms |
| 分页加载 | < 300ms |

- [ ] SQLite 索引优化
- [ ] FTS5 查询优化
- [ ] 分页策略

#### 4.4 内存优化

- [ ] 空闲内存 < 300MB
