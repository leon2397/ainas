# ADR-002: 产品范围收缩与多形态并行

- **状态**：已接受
- **日期**：2026-10-18
- **决策者**：项目负责人

## 背景

历史规划中并行着多条产品线：AI-NAS 套件、英语学习助手、CRMpro、硬件盒子（V8 蓝图）。团队仅 3 人，且英语助手源码不在本机、CRMpro 无源码。

## 决策

1. **英语学习助手、CRMpro 撤出范围**（源码缺失，不再讨论）
2. **硬件盒子（V8）压后为储备**：只维护设计文档，RKNN demo 验证前不启动
3. **"多款产品"落地为 ainas-nas 一个底座、四种交付形态并行迭代**：

| 形态 | 优先级 | 说明 |
|------|--------|------|
| Docker 镜像 | P0 | 生产形态，AI 功能完整 |
| DSM 套件 | P1 | 群晖/威联通渠道 |
| Windows 客户端 | P2 | 个人用户体验 |
| RN 移动 App | P3 | 移动端 |

## 理由

- 方向用数据选，不预先赌：四种形态各自独立版本线，用市场信号（下载量/付费转化/留存）决定加注方向
- 源码缺失的线没有讨论价值，沉没成本不追
- 3 人团队不同时开超过两条活跃线

## 方向评审机制

每个形态满 3 个版本或第 12 周，开信号评审会：达标加注、不达标降级。评审数据口径在各形态上线时确定。

## 后果

- 全部工程资源集中到 ainas-nas 底座质量（这正是 v1.0.0 重建在做的事）
- 英语/CRM 相关历史文档留在 archive/，不再更新
- 硬件方向保留 V8 文档火种，不消耗人力
