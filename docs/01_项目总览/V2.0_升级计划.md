## 方向声明

**目标客户**：个人用户（NAS 私有云所有者）
**产品形态**：Docker 单容器，一键部署到群晖/威联通/Ubuntu/Windows Server
**核心价值**：把散落在 NAS 各处的照片视频，用 AI 整理得井井有条
**变现路径**：SaaS 订阅（基础免费 + 高级功能付费）/ 一次性买断（软硬一体机）

> **排除项（商用阶段再做）**：
> - 企业 SSO / 多租户 / 审计日志
> - QQ小程序 / 移动端 App
> - K8s 部署（docker-compose 是主流程）
> - ARM 双服务端（Jetson/RK3588/BM1688）

## Phase 2：产品完善（Week 6–Week 8）

**目标**：根据种子用户反馈打磨，补充高优先级功能

### 2.1 性能优化 🔴 P0

- [ ] 媒体扫描性能（1 万张照片 < 10 分钟）
- [ ] 缩略图生成性能（< 500ms 每张）
- [ ] 相册列表查询（< 200ms）
- [ ] ChromaDB 向量搜索性能验证
- [ ] 内存占用优化（目标 < 500MB 空闲）

### 2.2 存储插件架构重构

- [ ] 统一 `FileStorage` 基类
- [ ] 支持 SMB/CIFS（群晖/威联通常见）
- [ ] 支持 SSH/SFTP
- [ ] 插件注册表规范化

### 2.3 安装包体系 🔴 P0（阻塞商用）

- [ ] **DEB 安装包**（Debian/Ubuntu `dpkg -i ai-nas.deb`）
- [ ] **RPM 安装包**（CentOS/RHEL `rpm -i ai-nas.rpm`）
- [ ] **Windows 安装包**（InnoSetup/NSIS）
- [ ] 卸载干净（不留注册表/配置文件）

### 2.4 安全性加固

- [ ] JWT secret 默认强制设置（不设不让启动）
- [ ] 密码强度要求（禁止弱密码 admin123）
- [ ] API 限流（防止恶意请求）
- [ ] 敏感信息不上日志

### 2.5 监控与运维

- [ ] 健康检查端点 `/health`
- [ ] 监控指标 `/metrics`（请求量/响应时间/错误率）
- [ ] 日志轮转（不撑爆磁盘）
- [ ] 自动备份机制

**Phase 2 验收标准**：能在群晖/威联通实机上安装，1 万张照片从扫描到可搜索 < 15 分钟。
